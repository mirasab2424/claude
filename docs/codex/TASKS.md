# Задачи для Codex

Сначала прочитай `AGENTS.md` в корне репозитория: там правила проекта и как устроена выкладка.

## Общие правила для каждой задачи
- Одна задача — одна ветка и один pull request в `main`. Название PR — по-русски, коротко.
- Каждая задача трогает только свои файлы (они указаны). Тогда задачи можно делать параллельно
  и PR не конфликтуют. Если без правки чужого файла никак — правка минимальная, 1–3 строки.
- Ничего не выдумывать: данные пользователя, размеры дома и факты не придумывать.
- Трекер: перед PR `php artisan test` должен быть зелёным. Подготовка среды:
  `composer install && cp .env.example .env && php artisan key:generate`
  (тесты идут на SQLite в памяти, база не нужна). Рабочую базу и `migrate:fresh` не трогать, миграций не добавлять.
- «Наш дом» (`sites/miras/public`) — статический сайт на Three.js 0.160 без сборщика (`import * as THREE from 'three'`
  через importmap в `3d.html`). Проверка: `python3 -m http.server 8765` из `sites/miras/public`, открыть `3d.html`,
  в консоли браузера не должно быть ошибок. Сцена должна идти на телефоне: общие материалы и геометрии,
  `InstancedMesh` для повторов, без лишних теней и источников света.
- В `sites/miras` при изменении любого `.js` подними версию `?v=22` → `?v=23` во всех импортах и `<script>` всех html
  (поиск по `?v=`), иначе браузеры возьмут старый файл из кэша. Если две задачи обе подняли до `v=23` — это не конфликт смысла,
  при слиянии оставь одно значение.
- Вечерний свет («Вечер»): светящиеся материалы добавлять в массив `night.glow`
  (вечером им ставят `emissiveIntensity` 2.6, днём 0.25), лампы `PointLight` (цвет `0xffc773`, без теней) —
  в группу, которая видна только вечером. Как это сделано — смотри `assets/decor.js` и где он вызывается в `assets/view3d.js`.

## Сайт «Наш дом» (miras.page.gd)

Координаты: x — вправо, если стоять на улице; глубина d — от забора на улице вглубь участка; в сцене z = −d, y вверх.
Дом строится в `assets/view3d.js` из `data/measurements.json` (миллиметры), группа `root`: x = мм/1000, z = −y_мм/1000,
пол на y = 0. Участок и пристройка — в метрах участка (`data/design.json`, раскладка пристройки — `outbuildingLayout()`
в `assets/house.js`, постройка — `buildOutbuilding()` в `view3d.js`). Стиль и помощники — `assets/decor.js`
(`houseFinish`, `yardDecor`): белая штукатурка `0xf1ece2`, графит `0x3c4046`, тёмные рамы `0x2f3338`,
дерево `0xb07a45` / `0x8a5a33`, цоколь `0x55514c`.

### 1. Интерьер комнат дома
Новый файл `assets/interior.js`, экспорт `addInterior({ h, root, openings, H, night })`;
вызов — одной строкой в `view3d.js` сразу после вызова `houseFinish(...)`.
- Плинтусы по периметру каждой комнаты (`h.rooms[].floor_polygon_mm.value`).
- Межкомнатные двери в проёмах (`openings` с `kind: 'door'`, кроме входной — у неё `d.between` содержит `'outside'`):
  полотно на петле, приоткрыто ~75°, ручка, наличники.
- Потолочный светильник в центре каждой комнаты (плафон на высоте `H − 50` мм), светится вечером.
- Шторы у окон первого этажа изнутри (`openings` с `kind: 'win'`, поля `axis, a, b, at, lo, hi, t` в мм;
  `axis: 'y'` — стена вдоль x на y = at), по краям окна, окно не закрывать.
- Ковры в двух-трёх самых больших комнатах. Потолок не делать: дом смотрят сверху без крыши.
- Не мешать прогулке: в проёмах дверей ничего не ставить.

### 2. Обстановка пристройки
Новый файл `assets/ob_interior.js`, экспорт `addOutbuildingInterior({ L, groundY, group, night })`.
В `view3d.js`: вызов после `buildOutbuilding(...)` и удаление простых ящиков-заглушек в блоке
«немного обстановки» внутри `buildOutbuilding` (кухня, асхана, столярка, баня, кладовая; машину и стеллаж гаража не трогать).
- Кухня: гарнитур с мойкой и плитой, холодильник, верхние шкафы.
- Асхана: длинный стол (дастархан) на 10–12 человек со скамьями, буфет, ковёр.
- Столярка: верстак с тисками, стеллаж с инструментом, станок, доски у стены.
- Предбанник: лавки, вешалка, стол. Баня: полки в два яруса, печь-каменка с камнями.
- Туалет: унитаз, раковина. Кладовая: стеллажи с банками и коробками.
- Гараж: верстак у задней стены, шины, велосипед; не пересекаться с машиной (`L.car`: x1, x2, d1, d2).
- Лампы в каждой комнате (вечером светятся). Барбекю-зону не трогать — там уже мангал, печи и стол.
- Не загораживать двери (`L.ob.doors`, учитывать, куда открываются створки) и проходы.

### 3. Фасад пристройки
Новый файл `assets/ob_facade.js`, экспорт `addOutbuildingFacade({ L, groundY, group, roofGroup, night })`;
вызов в `view3d.js` после `buildOutbuilding(...)`.
- Тёмный цоколь 0,3 м по стене со стороны двора (x = `L.x1`) с разрывами в дверях и открытой барбекю-зоне.
- Тёмные рамы, импосты и отливы окон (`L.ob.windows`).
- Наличники и козырьки над дверями во двор, светильники у дверей (вечером светятся).
- Крыша (в `roofGroup`): лобовая доска по краю, водосточный жёлоб и трубы, фальцы на скате.
- Барбекю-зона: деревянные ламели на боковых стенках, зонт-вытяжка над мангалом с трубой над крышей.
- Ворота гаража: секционные панели, рама, ручка — поверх существующих ворот.

### 4. Ещё детали двора
Новый файл `assets/yard_extra.js`, экспорт `addYardExtras({ group, groundY, plot, L, house, night })`;
вызов в `view3d.js` сразу после `yardDecor(...)` с теми же аргументами.
Занятые места (x, d в метрах): дом x 3.0–15.4, d 3.7–17.3; плитка вокруг дома x 1.8–17.2, d 2.2–19.5;
проезд x 17.2–21.8, d 0–29 и x 10.6–17.2, d 19.5–29; беседка x 1.8–5.0, d 20.9–24.7;
детская площадка на песке x 6.6–10.6, d 19.5–26 (качели на d 24.6, песочница у d 20.3);
огород x 0–10.6, d 26–35.9 (шесть грядок); терраса с перголой x 11.4–16.4, d 29.9–34.2; сад x 17–22.5, d 29.5–35;
пристройка x 22.9–27.9, дорожка вдоль неё x ≈ 22.35; ворота во двор x 15.9–21.6 на d = 0.
- Огород: бочка и лейка, компостный ящик, шпалеры на двух грядках, пугало, бортики грядок из досок.
- Детская площадка (свободная часть x 6.8–10.4, d 21–24): горка, домик или лазалка, бортик песочницы.
- Беседка: гирлянда по краю крыши и подвесной фонарь (вечером светятся).
- За домом (d 17.4–19.3, x 4–10): уличный стол со стульями или шезлонги, сушилка для белья.
- Забор на улице (d = 0, x 0–15.9): кирпичные столбики каждые ~2,8 м, у ворот — столбы повыше с фонарями.
- Собачья будка, шланг на катушке у стены дома, камни и кусты.

### 5. «Экскурсия» по 3D
Менять только `3d.html`. Кнопка «Экскурсия» в панели: список остановок и кнопки «‹ ›».
Камера — `v.setCamera([px, py, pz, tx, ty, tz])` (мгновенно), текущая — `v.getCamera()`;
плавный переход ~900 мс сделать в `3d.html` через `requestAnimationFrame`. Слои включать кликом по кнопкам `[data-layer]`.
Перед экскурсией выйти из «Прогулки». «Вечер» после экскурсии вернуть как был. Стрелки клавиатуры не занимать (их использует прогулка).
Остановки (cam = px,py,pz,tx,ty,tz), к каждой — подпись в одно предложение:
1. Общий вид участка — `-9,13,14,12,0,-14`
2. Крыльцо — `1,3.2,2.5,9,1.2,-6`
3. Проезд и гирлянды — `19,2.2,-2,20,1.2,-12`
4. Барбекю-зона — `17.5,3,-6.5,24,1,-9`
5. Гараж с машиной — `22.2,8.5,3.8,25.4,0.4,-3.2` (крышу выключить)
6. Зона отдыха с перголой — `7,5,-24,19,0,-33`
7. Беседка и огород — `10,6,-18,3,0,-28`
8. Вечер во дворе — `6,7,6,17,0,-12` + включить «Вечер»
Везде, кроме п. 5, включены слои «Крыша», «Двор», «Постройки», «Мебель». На ширине 360 px ничего не должно ломаться.

**После слияния задач 1–5:** выложить сайт вручную — GitHub → Actions → «Deploy miras.page.gd» → Run workflow, `clean_slate` = false.

## Трекер (to-do-miras.page.gd)

Выкладывается сам после слияния в `main`. Образцы: страницы `app/Filament/Cabinet/Pages/*`
(`WeekReviewPage`, `Calendar`, `Timeline`), сервисы `app/Services/*` (`WeekReview`, `Coach`), тесты `tests/Feature/*`.
Страницы кабинета подключаются сами (`discoverPages`). Только данные текущего пользователя, каждое действие
проверяет, что запись принадлежит `auth()->id()`. В Filament-замыканиях параметры по имени: `$query`, `$record`, `$state`.

### 6. Страница «План дня»
Новые файлы: страница `/cabinet/day-plan` (группа «Обзор»), её blade-вид, сервис `App\Services\DayPlan`,
тест `tests/Feature/DayPlanTest.php`.
- Выбранный день (по умолчанию сегодня), кнопки «‹ вчера», «завтра ›», «Сегодня».
- Задачи со сроком на этот день и просроченные незавершённые; привычки на день с отметкой
  (`habits` + `habit_checks`, одна отметка в день — логику взять из виджета `HabitsToday`); запись «Как прошёл день», если есть.
- Действия: отметить задачу / вернуть, «перенести на завтра» (+1 день к сроку), отметить / снять привычку.
- Сверху полоса «сделано N из M».
- Тесты: страница открывается, чужие задачи не видны и не меняются, отметка и перенос работают.

### 7. Страница «Итоги месяца»
Новые файлы: страница `/cabinet/month-review` (группа «Обзор»), blade-вид, сервис `App\Services\MonthReview`,
тест `tests/Feature/MonthReviewTest.php`.
- Выбор месяца «‹ ›», по умолчанию текущий.
- Цифры месяца и сравнение с прошлым (стрелка и разница): выполнено задач, достигнуто целей, отметок привычек и % выполнения,
  средние шаги и сон (метрики «Шаги» и «Сон»; сон в секундах, `is_duration`), среднее настроение и энергия из `day_logs`,
  число записей метрик.
- Лучший день месяца, самая длинная серия привычки, тепловая сетка-календарь активности по дням.
- Пустое состояние, если данных нет.
- Тесты: расчёты на фиксированных датах (`CarbonImmutable`), страница открывается, чужие данные не попадают.

### 8. Новые советы тренера
Менять только `app/Services/Coach.php` и `tests/Feature/CoachTest.php`. 6–8 новых правил в стиле существующих,
каждое — только при достаточных данных; существующие тесты не ломать, предупреждения остаются первыми.
- Серия привычки от 7 дней — похвала; «серия под угрозой»: вчера отмечено, сегодня нет, серия ≥ 3.
- Привычка не отмечалась 7+ дней.
- Настроение / энергия за 7 дней упали на ≥ 1 балл против предыдущих 7 — мягкий совет; выросли — похвала.
- «Как прошёл день» не заполнялся 3+ дня (если раньше заполнялся).
- Больше 7 задач на сегодня — выбрать три главные; нет задач на сегодня при активных целях — запланировать шаг.
- Цель без движения 14+ дней.
- Шаги: неделя к неделе −20 % и больше — предупреждение; 3 дня подряд больше 10 000 — похвала.
- Сон: разброс длительности за 7 дней больше 1,5 ч — совет про режим.
На каждое правило — тест с фиксированной датой, включая «данных мало — совета нет». Тексты короткие, с числами.

### 9. Проверка публичной части
Менять только публичные шаблоны (`resources/views` вне `filament/`) и `public/css/*`, `public/js/*`
(кроме `public/js/logo3d.js` и `public/vendor`).
- Главная и `/u/miras` на ширине 360, 768 и 1280: ошибки консоли, горизонтальная прокрутка, вылезающие блоки,
  мелкие кнопки, контраст, битые ссылки и картинки.
- Доступность и SEO: `alt`, подписи кнопок, порядок заголовков, `lang`, meta description, Open Graph.
- Экранирование: `{{ }}`, а не `{!! !!}` для пользовательских строк; строки во всплывающих окнах карты — через `escapeHtml`.
- Приватное не показывать (`UserStats` с `publicOnly`). Логотип не перерисовывать.
- Для локальной проверки — отдельная база: `DB_DATABASE=/путь/к/временной.sqlite php artisan migrate --seed`.

### 10. Проверка кода кабинета
Найти и исправить реальные ошибки и дыры в `app/Filament/Cabinet/**`, `app/Filament/Shared/**`, `app/Models/**`,
`app/Services/*` (кроме `Coach.php` — это задача 8), `routes/web.php`. Тесты — в новом `tests/Feature/CabinetHardeningTest.php`.
- Утечки чужих данных: фильтр `user_id` в каждом ресурсе кабинета, подстановка `user_id` при создании,
  проверка владельца в действиях страниц и виджетов; публичная страница без приватного.
- Массовое присваивание (`is_admin` намеренно не в `$fillable`), валидация, «одна запись в день» (`habit_checks`, `day_logs`).
- Даты и часовые пояса, деление на ноль, пустые коллекции, N+1 на инфопанели.
- Импорт Samsung Health (`SamsungHealthImport`): битые CSV и zip, пути с `../`, zip-бомбы, лимиты размера,
  ручные записи не перезаписываются.
Без косметических рефакторингов: только подтверждённые проблемы, каждая с тестом.
